## 二、本轮实际踩到的坑 (已修复, 引以为戒)

### F-01 FieldType 双包名残留 (M1 坑的尾部)
`FieldType` 唯一正身在 `com.zifang.z.report.common.schema`; `dataset.engine` 包从来没有它。
M1.5 批量替换后 `DataSourceController` 仍残留一处 `import ...dataset.engine.FieldType`, 单独 `-pl z-report-web -am` 编译必炸。
**教训**: 批量替换后必须 `grep -rn "dataset.engine.FieldType" --include="*.java"` 确认清零; 旧 snapshot jar 在 .m2 里会掩盖编译错误 (stale jar 有旧类), 全量 clean test 才可信。

### F-02 测试断言与数学事实不符 (3 处, 全是我写错)
- `1 + amount*2/2` (amount=100) = **101**, 断言写成 103
- `(amount+qty)*100/100` = **103**, 断言写成 150
- `city IS NOT NULL` (city 非空) = **true**, 断言写成 false
**教训**: 断言失败先手算表达式求值链, 再怀疑解析器; 本轮 3 个失败全部是断言错, 解析器无 bug。

### F-03 发布 token 行为变化连带测试 500
`getPublication` 加 token 强制校验后, 端到端测试观看侧请求没带 token → @RequestParam 缺失 500。
**教训**: 改 SPI 签名必须 grep 全部调用点 (含测试); `grep -rn getPublication` 本应立刻暴露 EndToEndFlowTest。

### F-04 mvn 单模块构建必须 -am
`mvn compile -pl z-report-web` 报 `Could not find artifact io.github.yuku123:z-report-ai` —— reactor 内模块没 install 过, 单独 -pl 解析不到兄弟模块 SNAPSHOT。
**规则**: 本工程一律 `mvn <goal> -pl <module> -am`, 且加 `-Dsurefire.failIfNoSpecifiedTests=false` 防无测试模块报错。

### F-05 前端执行环境 PATH
沙箱 shell 默认 PATH 无 npm/node (nvm 安装)。需要:
`export PATH="$HOME/.nvm/versions/node/$(ls $HOME/.nvm/versions/node | tail -1)/bin:$PATH"`
npm install (138 包, 9s) 与 vite build 在沙箱均验证通过。

## 三、留给同伴的坑 (按优先级)

### P-01 持久化落地 (M2.5 主线)
- Hook: `web/store/SchemaStore` 接口 (语义: require\* 抛 IAE / get\* 返 null / put\* upsert) + `book/BookService`
- DDL 就绪: `_doc/sql/001_schema.sql`; schema 全文 JSON 列 (Jackson 直接反序列化 common.schema 内的 POJO)
- 做法: MyBatis-Plus 实现 `JdbcSchemaStore` 替换 `InMemorySchemaStore` 的 @Component; BookService 同理 (节点树邻接表, order 列名是 **order_no**, order 是保留字)
- 坑: 节点树递归组装在 DB 版要么多次查询要么递归 CTE; 内存版 `InMemoryBookService.tree()` 可作行为基准 (已有测试)

### P-02 数据集结果缓存的失效语义
`CachingDatasetExecutor` 是单机内存 TTL 版 (60s), TTL 内源数据变更**不会**反映到渲染。
- 单机够用; 多实例部署需换 Redis/z-cache
- 更优方案: 数据集定义 put 时主动 `invalidateAll()` (现在没挂 hook), 或按 sourceId 维度失效

### P-03 z-util-expr 接入 (计算字段增强)
`ExprParser` 白名单: 列/字面量/算术/比较/逻辑/IS NULL/IN/LIKE, **无函数调用、无日期运算** (刻意设计, 见 ExprParser 类注释)。
接入点: `DatasetExecutor.executeTable` 的 computedFields 段。
**硬约束**: 接入 z-util-expr 后必须白名单限定可用函数 (禁止任意求值), AI 生成的表达式一样过校验。

### P-04 渲染端点权限缺口 (安全)
观看页流程: `getPublication(publishId, token)` (有校验) → 拿 viewId → `GET /api/render/view/{viewId}` (**无鉴权, viewId 可枚举**)。
M2 语义是"匿名分享", 若要收紧: render/view 对观看侧要求 publication token 换发短期 view-token, 或 viewId 加密/带签名。
**接手时请和用户确认安全水位**, 内网 demo 可暂缓。

### P-05 数据源凭证加密
`DataSourceDef.properties` 明文存连接串/密码; DDL 里 `report_data_source.config` 是 JSON 列。
落库前需应用层加密 —— z-boot 体系是否已有加解密/KMS 组件**未调研**, 请先找 (z-config? z-opc?) 再造轮子。

### P-06 前端 chunk 过大
echarts 全量引入 → dist 1.3MB (gzip 433KB)。
改法: `import * as echarts from 'echarts/core'` 按需注册 + `manualChunks` 拆 vendor。非阻塞, 首屏内网可接受。

### P-07 大表渲染截断 (约定, 非 bug)
`TableWidget` 前端截断 200 行 (MAX_RENDER_ROWS); 数据源头 maxRows=100000 (JdbcReportDataSource)。
真分页需要: 后端 rows 切片 API (offset/limit) + 源层 SELECT 直翻页, 现引擎是全量内存模型, 动之前先看 P-09。

### P-08 执行引擎全量内存语义
`DatasetExecutor`: 源全量读入内存 → join → 计算列 → 过滤 → 聚合。无谓词下推、无 limit 下推。
maxRows 是防 OOM 兜底不是分页。大表场景 (方案 5.2) 的下推优化未做, AI 生成视图时对大表会真实全量执行 (AiController.toView 里 fields 缺失时还会 executeTable 取列头, 已在代码注释标注)。

### P-09 AI 生成质量未实测真实 LLM
`AiReportServiceTest` 用 mock LlmClient 验证的是提示词组装+契约校验拦截。
真实 OpenAI 兼容端点未调用过 (无 key): prompt 模板效果、JSON 稳定性 (是否需要 response_format/json_schema)、幻觉率, 全部待真实联调。
配置入口: `z.report.llm.api-key` / `z.report.llm.base-url` / `z.report.llm.model` (或环境变量 LLM_API_KEY)。

### P-10 前端编辑器 (M4) 未开工
现在只有渲染侧; 拖拽编辑器产出 ViewSchema (widgets+layout 同协议) 后直接走既有渲染链路。
布局协议: 12 列 grid, layout 单元 {widgetId,x,y,w,h}, 行高前端定 60px (UniversalRenderer.ROW_H)。
